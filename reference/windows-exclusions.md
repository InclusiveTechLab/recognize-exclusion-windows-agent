## Device Manager Hardware Tree

**User action:** User browses, updates, or troubleshoots device drivers in Device Manager.

### Perceivable

- Warning icons on failing devices are small yellow triangles without text labels; users with low vision miss the alert.
- Tree-view expand/collapse arrows are tiny and lack visible focus rings; state changes aren't obvious.
- Driver update status appears as a brief toast that fades before users notice it.
- Error-state devices rely on a yellow-vs-green icon distinction alone; color-blind users can't differentiate.
- The properties dialog layers multiple tabs with dense text; critical information is buried visually.

### Operable

- Expanding nested device categories requires precise clicks on small arrow glyphs; mis-clicks collapse the wrong branch.
- "Update driver" and "Uninstall device" are adjacent with no confirmation spacing; accidental selection is easy.
- Right-click context menus dismiss if the pointer drifts slightly; users with tremor lose access.
- Scanning for hardware changes has no keyboard shortcut; users must navigate the Action menu each time.
- The properties dialog requires tabbing through many controls to reach driver details; keyboard navigation is lengthy.

### Understandable

- Device names use hardware IDs ("PCI\VEN_8086&DEV_A370") instead of friendly names; users can't identify their hardware.
- "Roll Back Driver" doesn't explain what version it will restore or what changes will revert.
- Error codes (e.g., "Code 43") appear without plain-language descriptions or suggested next steps.
- "Disable device" vs. "Uninstall device" consequences aren't distinguished; users risk removing drivers permanently.
- The difference between "Update driver automatically" and "Browse my computer" isn't explained in context.

## Disk Management Console

**User action:** User creates, resizes, or formats drive partitions.

### Perceivable

- Partition color-coding (blue for primary, green for extended) carries no text legend on the volume bar itself.
- Unallocated space appears as a thin black sliver between partitions; users with magnification may not spot it.
- Volume health indicators rely on icon overlays that blend into the toolbar at standard DPI.
- The graphical disk map uses proportional sizing; very small partitions are nearly invisible.
- Status text ("Healthy", "At Risk") appears in a narrow column that truncates without tooltip on hover.

### Operable

- Right-clicking a partition to extend or shrink requires targeting a narrow graphical bar; keyboard selection is indirect.
- "Delete Volume" is one click away from "Extend Volume" in the context menu with no undo or confirmation delay.
- Initializing a new disk requires choosing MBR vs. GPT in a modal with no back button; wrong choice requires reformatting.
- Resizing a volume uses a spinner control with no direct text entry; precise sizing is tedious with arrow keys.
- The console is an MMC snap-in; standard Windows keyboard shortcuts like Ctrl+Z don't apply.

### Understandable

- "Simple", "Spanned", and "Striped" volume types are listed without explaining redundancy or data-loss risk.
- "MBR" and "GPT" partition styles use acronyms without inline definitions; users can't make an informed choice.
- "Shrink Volume" dialog shows "available shrink space" without explaining why it differs from free space.
- Drive letter assignment doesn't warn that some apps hardcode paths and may break after a change.
- "Active" partition marking has no explanation of what it controls or when it matters.

## Taskbar Calendar and Clock Flyout

**User action:** User clicks the clock to view date, calendar, and upcoming events.

### Perceivable

- Today's date highlight is a thin circle that blends into the grid; users with low vision miss which day is current.
- Event previews truncate after a few words with no tooltip; users can't read full event titles without clicking through.
- The month transition animation slides quickly; users relying on magnification lose their place in the calendar grid.
- Tiny left/right arrows for month navigation have no text labels; screen magnifier users may not find them.
- Secondary time zones display in a smaller font below the primary clock; the hierarchy isn't visually distinct.

### Operable

- Calendar grid cells aren't individually focusable with Tab; arrow-key navigation requires discovering the pattern.
- Clicking an event opens the Calendar app full-screen; there's no inline expansion to preview details without leaving the flyout.
- The flyout dismisses on any click outside it; users who accidentally tap the desktop must reopen and re-navigate.
- Adding a new event from the flyout requires a multi-step redirect to the Calendar app; there's no inline creation.
- Scrolling through months requires repeated arrow clicks; there's no jump-to-month or keyboard shortcut.

### Understandable

- Events from multiple accounts are color-coded but the legend is only visible inside the full Calendar app, not the flyout.
- "Focus time" blocks from Outlook appear without explaining how they interact with Windows Focus Assist.
- All-day events and timed events are listed together with no visual grouping; the schedule structure is unclear.
- The flyout shows a notification count badge but doesn't explain its relationship to Action Center alerts.
- Time zone labels use abbreviations (PST, EST) without full names; users in non-US zones may not recognize them.

## OneDrive Sync Status Overlay

**User action:** User monitors or troubleshoots file sync status from the system tray OneDrive icon.

### Perceivable

- Sync progress uses a tiny circular spinner on the tray icon; users can't distinguish syncing from idle at a glance.
- File-level sync icons (green check, blue arrows, red X) are 12-pixel overlays on Explorer thumbnails; they're invisible at standard scaling.
- Conflict notifications appear as brief toasts that vanish before users notice a file version mismatch.
- The "paused" state looks nearly identical to "up to date" in the tray icon; only a subtle pause glyph differs.
- Bandwidth throttling status is shown only inside the settings panel; there's no tray-level indicator of reduced speed.

### Operable

- Clicking the tray icon opens a flyout, but navigating to sync errors requires scrolling a list with no filter or search.
- Pausing and resuming sync requires right-clicking the tray icon and finding the option in a nested menu.
- Resolving a file conflict opens a browser-based comparison with no way to resolve inline from the desktop.
- "Free up space" on individual files requires right-clicking each one; there's no batch selection in the flyout.
- The settings dialog is a separate window that doesn't persist position; users must reopen and relocate it each time.

### Understandable

- "Files On-Demand" status icons (cloud, solid green, green outline) aren't defined anywhere in the flyout or tooltip.
- "Available when offline" vs. "Always keep on this device" aren't distinguished in plain terms; the difference is unclear.
- Sync error messages reference SharePoint library permissions without explaining how to resolve them locally.
- "Personal Vault" lock/unlock state isn't reflected in the tray flyout; users don't know if sensitive files are exposed.
- Storage quota warnings use percentages without showing absolute values; users can't gauge how many files fit.

## Windows Terminal Profile Switcher

**User action:** User selects, configures, or switches between shell profiles in Windows Terminal.

### Perceivable

- Profile tabs use small colored underlines to indicate the active shell; the color distinction is subtle at default scaling.
- Command output scrolls rapidly with no visual pause indicator; users with low vision lose context in fast-moving text.
- The dropdown profile menu shows shell names but not icons at higher DPI; profiles look identical.
- Bell/alert events in terminal flash the tab title briefly; users not watching the tab bar miss the notification.
- Split-pane dividers are a 1-pixel line; users with magnification can't perceive the boundary between panes.

### Operable

- Opening a new tab in a specific profile requires a dropdown hover-then-click sequence; keyboard shortcuts vary by configuration.
- Resizing split panes requires dragging a nearly invisible divider; there's no keyboard-based resize command exposed in the UI.
- Copying text selection requires a right-click or Ctrl+C that can conflict with terminal SIGINT; users inadvertently kill processes.
- Profile settings are in a JSON file by default; GUI settings exist but don't cover all options, forcing manual editing.
- Switching between tabs has no visual animation or audio cue; users lose track of which profile is active.

### Understandable

- "Default profile" vs. "startup profile" isn't distinguished; users can't predict which shell launches on open.
- Color scheme names ("One Half Dark", "Tango") don't describe contrast levels or suitability for low vision.
- "Shell integration" and "experimental features" toggles lack inline descriptions of what they enable.
- The relationship between Windows Terminal settings and individual shell configs (e.g., PowerShell profile.ps1) isn't explained.
- "Quake mode" and "focus mode" are named without describing their visual behavior or how to exit them.

## Startup Apps Configuration

**User action:** User enables, disables, or reviews apps that launch at sign-in.

### Perceivable

- Impact ratings ("High", "Medium", "Low") in Task Manager use text only in a narrow column that truncates on smaller displays.
- The Settings startup list and Task Manager startup tab show different app sets with no visual indication of overlap.
- Disabled apps are greyed out but remain in the same list position; the visual difference from enabled is minimal.
- Publisher names are truncated without tooltips; users can't identify unfamiliar apps to decide whether to keep them.
- New apps added to startup don't trigger a notification; users don't perceive changes to their boot sequence.

### Operable

- Toggling an app requires finding it in an unsorted or alphabetical list with no search or filter option in Settings.
- Task Manager and Settings both control startup apps but neither links to the other; users must know both locations.
- There's no "disable all" or batch-select option; users must toggle each app individually across a long list.
- Removing a startup entry entirely (not just disabling) requires navigating to the app's own settings or the registry.
- Right-clicking for "Open file location" in Task Manager opens Explorer but doesn't highlight the target file consistently.

### Understandable

- "Startup impact" doesn't define what "High" means in seconds, CPU, or memory; users can't judge the real cost.
- The difference between "Startup apps" in Settings and the "Startup" tab in Task Manager isn't explained anywhere.
- Some entries show as "Not measured" for impact; users don't know if these are safe to leave enabled.
- UWP apps and Win32 apps are mixed in the same list without indicating which type affects boot differently.
- Disabling an app doesn't explain whether it can still run later or if background tasks are also stopped.

## File Properties and Security Permissions

**User action:** User views or modifies file attributes, sharing, and access permissions.

### Perceivable

- The Security tab lists permission entries in a dense ACL grid; "Allow" and "Deny" checkboxes are closely packed and hard to scan.
- Inherited vs. explicit permissions use the same checkbox style; there's no visual cue that some entries can't be changed here.
- The "Advanced" security dialog opens a separate window with smaller text and more columns; information density increases sharply.
- File attribute checkboxes (Read-only, Hidden) at the bottom of the General tab are easy to overlook below the larger fields.
- Sharing status ("Not shared" vs. share path) is plain text with no icon; users scanning quickly miss the sharing state.

### Operable

- Editing permissions requires clicking "Edit", then "Add", then typing exact user/group names; there's no browse-and-pick flow.
- "Take ownership" is buried three dialogs deep (Properties → Security → Advanced → Owner); the path is non-discoverable.
- Applying permissions recursively to subfolders requires a checkbox in the Advanced dialog that's easy to miss.
- Removing a user from the ACL requires selecting the row and clicking "Remove" with no undo; mistakes require re-adding manually.
- The "Share" tab and "Security" tab control overlapping access but are managed independently with no cross-reference.

### Understandable

- "Full control", "Modify", and "Write" permissions overlap in scope; users can't tell which to grant for simple file editing.
- "Special permissions" is listed as a category but clicking it opens an entirely new grid of granular options without explanation.
- Inherited permissions are described as "inherited from parent object" without naming the parent or explaining how to override.
- "Effective Access" tab requires selecting a user first but doesn't explain why results might differ from the visible checkboxes.
- "Read & Execute" vs. "Read" vs. "List folder contents" distinctions aren't clarified; users over- or under-grant access.

## Recycle Bin Management

**User action:** User restores, permanently deletes, or configures Recycle Bin behavior.

### Perceivable

- Recycle Bin icon switches between empty and full states, but the two icons are similar at small taskbar sizes.
- Deleted file original-location paths are shown in a narrow column that truncates; users can't see where the file came from.
- "Date Deleted" and "Date Modified" columns look identical in formatting; users confuse when the file was changed vs. removed.
- File type icons in the Recycle Bin don't preview content; users can't visually confirm they're restoring the right version.
- The "Size" column for Recycle Bin items shows individual file sizes but not cumulative space used without scrolling to properties.

### Operable

- "Restore all items" is a single click with no confirmation; users accidentally restore hundreds of files to scattered locations.
- Selecting multiple non-adjacent files for restoration requires Ctrl+Click precision; there's no checkbox mode like modern Explorer.
- "Empty Recycle Bin" is destructive and immediate; there's no secondary confirmation differentiating it from restoring.
- Per-drive Recycle Bin size limits are configured in a properties dialog that's hard to discover from the desktop icon.
- There's no search or filter within the Recycle Bin; finding a specific deleted file requires manual scrolling.

### Understandable

- "Restore" places files back to their original location, but if that folder was also deleted, the error message doesn't explain next steps.
- The difference between "Delete" (send to Recycle Bin) and "Shift+Delete" (permanent) isn't surfaced in any UI tooltip.
- Per-drive storage allocation for the Recycle Bin is shown in megabytes without context of total drive capacity.
- "Don't move files to the Recycle Bin" setting doesn't warn that this makes all future deletes permanent immediately.
- Items deleted from network drives or removable media bypass the Recycle Bin silently; users assume they can recover them.

## Windows Fonts and Typography Settings

**User action:** User installs, previews, or removes fonts from the system.

### Perceivable

- Font preview cards show a single sample sentence at one size; users can't gauge legibility at the sizes they actually use.
- Installed vs. available-to-download fonts are mixed in the same grid with only a small cloud icon differentiating them.
- Variable font weight ranges are represented by a slider with no numeric label; users can't perceive exact weight values.
- The font detail page shows character maps in a small grid; individual glyphs are hard to distinguish at default scaling.
- Font family groupings collapse variants (Bold, Italic, Light) under one card; users don't perceive how many styles are installed.

### Operable

- Installing a font from a downloaded file requires right-click → "Install for all users"; drag-and-drop to the Settings font page sometimes fails silently.
- Uninstalling a font has no undo; users who remove a system font must re-download and reinstall it manually.
- Searching the font list filters in real time but clears when navigating away; users must retype after viewing a font's detail page.
- There's no way to preview a font against custom sample text directly from the grid; users must click into each font individually.
- Font settings in the modern Settings app and the legacy Fonts control panel coexist; changes in one aren't always reflected in the other.

### Understandable

- Font metadata labels like "OpenType Variable" and "TrueType" aren't explained; users can't determine compatibility with their apps.
- "Install for all users" vs. default install scoping isn't clarified; users don't know if other accounts can see their fonts.
- The relationship between per-user fonts and app-specific font caches isn't described; some apps don't show newly installed fonts.
- "Font settings" includes a "Restore default font settings" button with no description of what it resets or which custom fonts it affects.
- ClearType tuning is in a separate wizard with no link from the Fonts page; users don't know font rendering can be adjusted.

## Sound Output Device Switcher

**User action:** User selects or switches between audio output devices from the taskbar or Settings.

### Perceivable

- The active output device is indicated by a small checkmark in the volume flyout; it's easy to miss among multiple devices.
- Device names are often generic ("Speakers", "Headphones") with no brand or port identifier; users can't tell which is which.
- When a Bluetooth device connects and auto-switches output, there's no persistent banner confirming the routing change.
- Volume level bars in the device list are thin and lack numeric readouts; users can't precisely perceive current levels.
- The flyout closes after selecting a device with no confirmation tone or visual flash; users aren't sure the switch took effect.

### Operable

- Renaming an audio device requires navigating into Settings → Sound → Device properties; there's no rename option in the flyout.
- Setting a device as "Default" vs. "Default communication device" requires the legacy Sound control panel; the modern UI doesn't expose both roles.
- Disconnecting a Bluetooth audio device from the volume flyout isn't possible; users must go to Bluetooth settings separately.
- Per-app audio routing is buried in Settings → Sound → Volume mixer; there's no way to assign an app to a device from the taskbar.
- Testing a device plays a generic tone with no visual indicator of which speaker is active; users must listen to confirm.

### Understandable

- "Default device" vs. "Default communication device" roles aren't explained; users don't know why Teams uses a different output than Spotify.
- "Spatial sound" options appear per-device but don't describe the audible effect or which content benefits from it.
- Devices listed as "Disconnected" remain in the list indefinitely; users don't know if they can be safely removed or will reconnect.
- Sample rate and bit depth options ("16 bit, 48000 Hz") in device properties use technical terms without explaining quality tradeoffs.
- "Exclusive mode" checkboxes don't explain that enabling them lets apps lock out other audio sources.

## Family Safety and Child Account Controls

**User action:** User configures screen time limits, content filters, or activity reports for a child account.

### Perceivable

- Activity report summaries use stacked bar charts with thin color segments; distinguishing app categories is difficult at a glance.
- Screen time remaining shows as a small countdown in the system tray; children and parents can't perceive it without hovering.
- Content-blocked notifications appear briefly and use generic wording; users can't tell which specific filter triggered the block.
- App usage percentages are displayed in a dense table without visual bars; comparing relative usage across apps is hard.
- Location sharing status is a toggle with no visible confirmation of the child's current position in the parent view.

### Operable

- Setting per-app time limits requires navigating into each app individually; there's no batch-select to apply the same limit to a group.
- Extending a child's screen time when they send a request requires the parent to open the Family Safety app or website; there's no inline approval from the notification.
- Age-rating content filters use different scales (ESRB, PEGI) but the selection interface doesn't explain which standard applies in which region.
- Removing a family member from the group requires signing into the Microsoft account website; it can't be done from Windows Settings.
- Overriding a blocked website requires typing the exact URL into an allow-list; there's no "allow this site" button from the block screen.

### Understandable

- "Web browsing" filters only apply to Edge; the scope limitation isn't stated clearly, leading parents to assume all browsers are filtered.
- "Screen time" vs. "App and game limits" are separate controls with overlapping effect; parents can't predict which rule takes priority.
- "Activity reporting" doesn't explain what data is collected or how long it's retained; privacy implications are unstated.
- "Content restrictions" references age ranges but doesn't describe what content types each age threshold blocks.
- The difference between "Family group" in Windows Settings and the Family Safety app on the web isn't clarified; settings appear in both with inconsistent detail.

## Registry Editor (regedit)

**User action:** User navigates, creates, or modifies registry keys and values.

### Perceivable

- The tree hierarchy is deeply nested with identical folder icons at every level; users lose visual context of their depth.
- Value names and data are displayed in a list with no type-based highlighting; DWORD, String, and Binary entries look the same until clicked.
- The address bar shows the full registry path in small text that truncates; users can't see the complete key location.
- Modified values don't show a timestamp or "changed" indicator; users can't perceive which entries were recently edited.
- The Favorites menu stores bookmarked paths as plain text names; there's no visual preview or grouping of saved locations.

### Operable

- Navigating to a known path requires manually expanding each tree node; pasting a path into the address bar is the only shortcut but isn't discoverable.
- There's no undo after editing or deleting a value; mistakes require manually re-creating the key or restoring from a backup.
- Exporting a single key produces a .reg file, but importing it back doesn't warn about overwriting existing values.
- Find (Ctrl+F) searches linearly through the entire registry with no progress bar; long searches appear frozen.
- Creating a new key or value requires right-clicking in the correct pane; the context menu differs between the tree and list panels.

### Understandable

- Data types (REG_DWORD, REG_SZ, REG_BINARY) use internal names without explaining what kind of data each stores.
- HKEY root names (HKEY_LOCAL_MACHINE, HKEY_CURRENT_USER) don't explain their scope or when to use which hive.
- Hexadecimal vs. decimal value entry is toggled by radio buttons in the edit dialog; users unfamiliar with hex enter wrong values.
- "Default" values that appear in every key aren't explained; users don't know if editing them has system-wide consequences.
- The relationship between Group Policy settings and their underlying registry keys isn't documented within the editor.

## Installed Apps and Default Programs

**User action:** User uninstalls apps, resets defaults, or manages optional features.

### Perceivable

- App list entries show name and size but truncate publisher information; users can't identify unfamiliar apps at a glance.
- Storage size values use abbreviated units (MB, GB) in a narrow column; apps near size boundaries (999 MB vs. 1.0 GB) look disproportionate.
- "Modified" dates blend into the row without emphasis; users can't quickly spot recently changed or updated apps.
- The "Sort by" and "Filter by" dropdowns are small icon-only buttons above the list; their function isn't apparent without hovering.
- Optional Features installation progress shows no per-feature status; users waiting for multiple features see one generic bar.

### Operable

- Uninstalling an app sometimes opens the app's own uninstaller with a different UI; the experience is inconsistent and occasionally modal.
- Resetting default apps requires selecting each file type or protocol individually; there's no "reset all to Windows defaults" single action.
- "Advanced options" for each app opens a separate page with no back shortcut; users must use the browser-style back arrow.
- Searching the app list clears when users click into an app and return; the filter must be retyped.
- Optional Features install with no cancel button once started; users must wait for completion even if the wrong feature was selected.
